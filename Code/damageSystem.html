BROKEN JAW – Damage System

Hover to play

Overview

Broken Jaw uses a localized damage model where individual skeletal regions have independent HP, damage reactions, and destruction behaviors. Core systems involved:

  • Per-component hit detection

  • Per-part HP tracking

  • Limb destruction (constraint breaking + physics)

  • Hit reaction routing (animations, Niagara VFX)

  • AI state updates (Blackboard)

  • Cached hit info → critical hit reprocessing

2. Damage Parts Definition

JawDamagablePartsList

Defines valid damage regions:

None, Chest_L, Chest_R, Abs, Leg_L, Leg_R

Used as the universal identifier for:

  • Damage lookup

  • Reaction selection

  • VFX configuration

  • Animation evaluation

3. HitReaction Data: FJawHitDataset

Designer-configurable hit response container:

  • AnimationToPlay: Montage to play on hit

  • CanSpawnNS: Enable Niagara FX

  • SpawnMeshComponent: Attach point for gore/blood

  • NSBlood / NSGore: FX systems

  • DamagePartName: Corresponding enum region

  • HasDamageMesh: Enables destruction mesh

4. Component → Damage Mapping

TMap<UPrimitiveComponent*, JawDamagablePartsList> DamagableParts

Maps collision primitives to damage zones. Used during hit resolution to determine which region was impacted.

5. Part Health

General Part Health

TMap<JawDamagablePartsList, float> PartsHealth

HP registry for torso and leg regions.

Special Arm Health

Arms use dedicated fields:

  • LeftShoulderHealth

  • RightShoulderHealth

  • LeftActive

  • RightActive

When HP hits zero:

  • Arm flagged inactive

  • Blackboard updated (LostLeftArm / LostRightArm)

  • Physical constraint broken

  • Optional mesh physics activated

  • ProcessDamage called for VFX/animation

6. Damage Flow

DamageToEnemy(FDamageToEnemyInfo DamageInfo)

Main entry point. Steps:

  1. Cache hit info (LastHitInfo).

  2. Apply global HP reduction via EnemyHealthComponent.

  3. Resolve hit component → detect limb hits.

  4. If limb health reaches 0:

    • Mark limb inactive

    • Trigger constraint break and physics

    • Update AI arm state (BrokenJawArms)

    • ProcessDamage for hit reactions

CriticalHit()

Re-dispatches previous hit into ProcessDamage. Triggered by the HealthComponent’s HitDelegate.

7. Hit Processing

ProcessDamage() – BlueprintNativeEvent

ProcessDamage(UPrimitiveComponent* HitComponent,
              FVector HitLocation,
              FVector HitNormal)

Purpose:

  • Spawn blood/gore FX

  • Play hit montage

  • Trigger destruction meshes

  • Apply region-specific visual/audio feedback

All localized response logic is routed through this function.

8. Animation + AI Integration

Animation

UBrokenJawAnimInstance receives updates for:

  • Arm loss

  • Reaction states

  • Behavioral transitions after damage

Blackboard Keys

  • PlayerRef: Cached reference to player

  • PlayerLoc: Updated every Tick

  • EyeSightLoc: Perception origin

  • LostLeftArm / LostRightArm: Limb destruction flags

  • BrokenJawArms: 0 = None, 1 = Both, 2 = One

Tick()

Constantly updates AI blackboard with:

  • EyeSightLoc

  • PlayerLoc

Ensures consistent tracking even while limbs are destroyed.

9. Limb Destruction

Upon limb HP reaching zero:

Mesh->BreakConstraint(HitNormal * Force, FVector::Zero(), BoneName);

Right arm additionally:

Mesh->SetAllBodiesBelowSimulatePhysics("upperarm_r", true);

Creates full detachment + ragdoll behavior.

10. Death Handling

Dead() calls parent class death logic.

Hook exists for future corpse/FX expansion.

11. Extensibility

To add new damage zones:

  1. Add to JawDamagablePartsList.

  2. Add HP in PartsHealth.

  3. Map collision component in DamagableParts.

  4. Configure FJawHitDataset entries.

  5. Extend ProcessDamage logic.

Highly modular and compatible with Doom-style progressive destruction.
