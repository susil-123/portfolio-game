Weapon System & Quickswap Mechanics — Technical Breakdown

Overview

This project features a fully modular weapon system designed around Doom Eternal’s philosophy of high-speed weapon cycling and animation-driven combat flow. The system is built through a dedicated Weapon Manager Component responsible for spawning guns, tracking weapon states, handling fire requests, and enabling animation-cancel quickswaps.

The result is a responsive arsenal where players can swap between weapons to bypass fire delays, enabling intentional “optimal DPS rotations” and skill-based quickswap tech.

1. System Architecture Overview

Component-Driven Weapon Handling

All weapon logic is handled inside UAC_PlayerWeaponManager, which manages:

  • Weapon spawning & pooling

  • Equipping / unequipping

  • Firing state (primary/secondary fire)

  • Ammo feedback to HUD

  • Animation event binding

  • Quickswap validations

  • Active/Previous weapon tracking

Each weapon (FireGun, SGun, TripleBlaster) inherits from AWeaponBase, ensuring consistent behavior while allowing custom firing logic per weapon.

2. Weapon Spawning & Initialization

At game start, the manager:

  • Reads weapon classes, montage data, and attach-point sockets from FWeaponManagerInitializer.

  • Spawns every weapon at runtime using SpawnGun().

  • Stores them in a TMap<PlayerGuns, AWeaponBase*> SpawnnedGunsMap.

  • Activates the starting weapon and deactivates the rest.

  • Attaches the active gun to the correct mesh socket.

This approach avoids runtime spawning during combat and enables instant weapon switching without hitches or spawn latency.

3. Equip / Unequip System (Animation-Driven)

State Machine

Weapon switching uses an animation-driven state system:

Unequip Montage → Equip Montage → ActivateGun Notify

The manager plays the correct montage pair based on the current and next weapon using:

  • UnEquipMontagesMap[CurrentGun]

  • EquipMontagesMap[NewGun]

Event Binding (Notify Begin → Callback)

Each montage is handled using: UPlayMontageCallbackProxy::OnNotifyBegin

This allows weapon transitions to synchronize precisely with animation Notifies:

  • “ChangeState” notify → swap internal weapon state

  • “ActivateGun” notify → allow firing

Prevents instant pops or desync between visual and gameplay states. This ensures a polished, AAA-style weapon presentation.

4. Firing System (Primary & Secondary Fire)

The manager exposes:

  • NFireCaller(bool Value);

  • SFireCaller(bool Value);

These route the input to the active weapon only if no gun change is in progress.

Each weapon implements:

  • NFire() – rapid fire, single shot, automatic, etc.

  • SFire() – alt-fire modes (charged blast, slug shot, explosive round)

Weapons remain dormant until activated, allowing real-time switching without persistent ticking on inactive guns.

5. Quickswap System (Doom Eternal-Style)

The core design goal was to enable fast, skill-based weapon swapping that bypasses weapon cooldowns.

Concept: Animation Cancel → Fire from New Weapon

In Doom Eternal, players quickswap by:

  1. Firing weapon A

  2. Cancelling recovery animation using weapon B

  3. Immediately firing weapon B

  4. Repeating back and forth

Your system achieves this with the following rules:

A) GunChangeInProgress Lockout

During a swap:

GunChangeInProgress = true;
CurrentGunRef->DisableGun();

This:

  • Prevents old weapon from firing during its recovery window

  • Enables swap-cancel only through animation notify triggers

  • Ensures swap consistency regardless of framerate

B) Animation Notify “ActivateGun” Re-enables Firing

At the exact notify frame:

CurrentGunRef->bIsGunActive = true;

if (bNFireDown) CurrentGunRef->NFire(true);
if (bSFireDown) CurrentGunRef->SFire(true);

This means:

  • If the player is still holding the fire button: The new weapon fires the moment the animation reaches the “ready” state.

  • If both weapons have short readies: The timing window becomes extremely tight — enabling rapid A → B → A → B quickswap fire loops.

C) Previous Gun Tracking for Instant Back-Swap

The manager maintains:

PlayerGuns PreviosGun;
AWeaponBase* PreviousGunRef;

This allows fast swapping: ChangeToPreviosGun();

Together with input buffering, this enables extremely fast cycle patterns such as:

  • FireGun → SGun → FireGun

  • SGun → Blast → SGun

  • TripleBlaster → FireGun → TripleBlaster

All while preserving the animation-driven cancel timing.

6. Weapon Attachments & Visual Consistency

Each weapon has a dedicated attach point: AttachPointMap[WeaponType]

The system:

  • Detaches the previous gun

  • Attaches new gun to its socket

  • Resets its transform

  • Activates/deactivates weapon behavior

This avoids snapping or offsets when switching back and forth multiple times per second.

7. Bullet Pooling

Fire weapons use a dedicated bullet pool: APlayerBulletPoolManager

This eliminates:

  • Spawn cost per shot

  • GC churn

  • Stutter during high fire rates (especially during quickswap chains)

8. HUD Integration

Whenever the weapon is fully equipped:

PlayerHudref->CurrentGun = GlobalRefToChangeGun;
PlayerHudref->UpdateGunAmmo();
PlayerHudref->UpdateAimImage();

This keeps the UI synced with the internal weapon state.

9. Design Philosophy — “Swap Is a Weapon”

Like Doom Eternal, your system treats weapon swapping itself as a combat mechanic.

Key rules:

  • Fast swap is always viable

  • Swap cancels recovery frames

  • Timing rewards the player

  • High skill expression → higher DPS

  • Encourages intentional weapon cycling instead of spamming one gun

This creates a combat loop centered around:

  • Optimized rotation

  • Rhythm

  • Timing

  • Swap skill ceiling
